# 需求卡片：L1-双阈值拒答

> 排期依据：阶段六（2026-10-07 访谈定案）。实现前填好，做完在 `progress-log.md` 记状态。
> **状态：2026-10-07 实现完成 ✅** —— 过程中两处判据被实测推翻并修正，见「实测结论」。

## 一句话

库外问题在「向量候选 raw 余弦**最高的一条**也低于强相关线 **且** 关键词路**证据不足**」时，
直接返回标准拒答、不再调用 LLM——把拒答从「依赖模型自觉」升级为「策略兜底」，
换更弱的 LLM 不失守，顺带省一次调用。

## 背景

`similarity_threshold=0.40` 是召回粗筛，但 kb_2 实测库外噪声会**高于粗筛线**（最高 0.4727）
照样进 prompt，拒答全靠 LLM 自己说「未找到相关信息」。换更弱的模型（turbo 级）时这道防线
**可能失守**：它会拿不相关上下文硬编答案。

## 实测结论（2026-10-07，本卡的两处判据修正）

⚠️ **两处「先量后改」，都是第一版的推论被实测推翻。** 教训已写进 `scripts/measure_refusal_gate.py`
的模块注释（该脚本就是为固化这个逐问验证而新增的）。

### ① 判据从「min」改成「max」

排期时用「kb_2 库内 rank-5 最低 0.4652 vs 库外最高 0.4726，两条分布重叠」说明
「向量分分不开」—— 那是 `measure_similarity_margin.py` 的口径（**最弱支撑切片**）。
但拒答要回答的是「**这题有没有强相关切片**」，正确统计量是 **max**：

| 库 | 库外 max 最高 | 库内 max 最低 | 结论 |
|---|---|---|---|
| kb_1（4 份 / 63 切片 / 13 问） | 0.3750（**低于粗筛线 → 门不参与**） | 0.6580 | 干净 |
| kb_2（3 份 / 75 切片 / 16 问） | 0.4727 | 0.7536 | **干净，根本不重叠** |

`0.48` 落在 `(0.4727, 0.6580)` 内。下界是紧的一侧（余量 0.0073）。

### ② 「关键词路 0 命中」不成立 → 改成「关键词证据不足」

原始设计断言「kb_2 库外探针在关键词路 0 命中」。**实测是假的**：`tokenize` 是中文重叠
2-gram，「美国站的退货窗口是多少天？」切出 `美国`，而 kb_2 里有「达到**美国**哪些条件就要
注册并申报销售税」的切片 → 关键词路非空。第一版写成 `not lexical_hits` 的后果：

> **双库 6 条库外探针全部漏网，门一次都没触发过。** 而 7 个离线单测全绿、469 项回归零红 ——
> **测试证明了机制，却没证明价值**（单测用 stub 造「关键词路为空」，真实分词永远造不出那个局面）。

修正后的判据用 **`lexical_overlap`**：关键词路返回的切片正文**实际覆盖了几个查询词**
（与存储无关、无量纲 —— chroma 的词分是「命中词数」、pgvector 是 `ts_rank`，
两者量纲不通，任何字面阈值都会在换存储时静默失准）。

| 库 | 库内最低覆盖 | 库外最高覆盖 | 门槛 |
|---|---|---|---|
| kb_1 / kb_2 | **2** | **1** | `LEXICAL_EVIDENCE_MIN_OVERLAP = 2` |

### 修正后的实际效果（kb_2 门开 vs 门关，`CACHE_ENABLED=false`）

指标层面**看不出差别**（门开/门关都是 命中 13/13、点名 13/13、拒答 3/3），
因为评测的 `拒答` 只认「没说未找到」，分不清是门拦的还是 LLM 自觉的。真正的差别在：
**门触发时 `sources=0`、零 LLM 调用、噪声切片不进 prompt**：

| 问题（kb_2 库外） | 门开 | 门关 |
|---|---|---|
| 皮具类的五金件电镀厚度有什么要求？ | **378ms / sources=0** | 1404ms / sources=5 |
| 美国站的退货窗口是多少天？ | **228ms / sources=0** | 2665ms / sources=5 |

第三问「今天的天气怎么样？」向量候选为空（低于粗筛线）→ **门不参与**，
走的是「检索为空」的老拒答路径（`sources=2` 来自关键词路，仍经 LLM 拒答）。这是正确分支。

## 输入 / 输出

- 输入：用户问题（`ask()` / `ask_stream()` 两条路径，含多轮改写后的检索词）
- 输出：正常回答（行为不变）；或门触发时 = `NO_HIT_ANSWER`（字面
  「资料库中未找到相关信息。」）+ `sources=[]` + **零 LLM 调用**，照常记 QaLog、照常进 K6 缓存

## 方案

- `Settings.answer_threshold: float`（默认 `0.48`，`0` = 关闭该门）
- `hybrid.py` 新增 `LEXICAL_EVIDENCE_MIN_OVERLAP = 2` 与 `lexical_overlap(query, hits)`
  —— 放在 hybrid 层是因为它定义的是「关键词路的证据强度」，且测量脚本与检索器要共用同一口径
- `Retriever.retrieve_gated()`：hybrid 模式下取向量路 + 关键词路双证据，返回 `(hits, refuse)`；
  vector 模式 / 门关闭时直接委托 `retrieve()`，恒 `(hits, False)`
- 管线在 `ask()` / `ask_stream()` 里收到 `refuse=True` 时把 hits 置空——
  **复用 Generator 既有的空检索路径**（不调 LLM、直接 `NO_HIT_ANSWER`），不新增生成侧分支
- 门触发记 DEBUG 日志（与「零命中静默」同一约定）
- 新增 `scripts/measure_refusal_gate.py`：逐问验证门在生产配置下拦谁放谁，
  退出码 1 = 误杀、2 = 门形同虚设（防止本卡的 ② 类问题复发且无人察觉）

## 依赖

- 前置积木：K3 批 2（0.40 粗筛与 `NO_HIT_ANSWER` 契约）、H1（关键词路）、K6（缓存键含 mode）

## 不做什么（边界，防止范围蔓延）

- 不动 `similarity_threshold=0.40`（召回粗筛保持不变）
- **不在 vector 模式启用门**（该模式没有关键词路这条证据；虽然实测 max 口径下也不重叠，
  但按定案保持现状，避免无谓的行为面扩大）
- 不给 inspect 质检台加门展示；不改前端（拒答形态与现在完全一致）
- 不做 PPT / OCR（L3）；不做管理后台 / 审计（L2）

## 失败点 / 风险

- ~~门限安全性依赖关键词路：kb_2 库内最弱 0.4652 < 门限 0.48，若该问关键词路 0 命中会误杀~~
  → **已实测排除**：① 门的统计量是 max（库内最低 0.6580，远高于 0.48）；
  ② 库内问题关键词覆盖最少 2 词，门槛 2 不会误判为「证据不足」。
- **门槛两侧余量不对称**：下界（库外噪声 0.4727）只有 0.0073 余量，上界有 0.178。
  语料变差时**先破下界**（噪声升高越过 0.48 → 门开始漏网）。重新测量时先看库外 max。
- 门限与 `LEXICAL_EVIDENCE_MIN_OVERLAP` 一样**过拟合当前语料 + 当前分词**：
  换语料、加文档、换 embedding 或改 `tokenize` 后，必须随
  `scripts/measure_refusal_gate.py` 重测（与 `measure_similarity_margin.py` 是**两个不同的统计口径**，
  数字不可互相引用）。
- 流式路径的拒绝必须发生在 `sources` 事件之前（契约：sources 先于 token）——
  实现上把 hits 置空后走既有路径，天然满足，但改动时别把门挪到 sources 之后。
- **K6 缓存键不含 `answer_threshold`**：开关门的 A/B 必须 `CACHE_ENABLED=false`，
  否则第二轮会命中第一轮的缓存（实测踩过：门关那轮 16 问平均 23ms，全部缓存命中）。
  这也意味着**门上线后，历史缓存里的「真答案」会继续被返回**——这是期望行为，
  不要为此改缓存键。
