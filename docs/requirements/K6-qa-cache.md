## 一句话
同样的知识库被反复问到相同/相近的问题时，直接返回缓存好的答案，不再重跑
「检索 → 重排 → 调大模型」；界面上能看出哪些回答是缓存命中。

## 输入 / 输出
- 输入：`ask` / `ask_stream` 请求（管线内部读写缓存）；`CACHE_*` 配置 4 项
- 输出：命中回答带 `cache_hit=true`（`AskResponse` + SSE `done` 事件 + 前端灰色
  「缓存」徽标）；文档增删后该库缓存自动失效

## 验收标准（可测试，逐条打勾）
- [x] 精确命中：同库 + 规范化同问（折叠空白 + lower）+ 同 mode + 同 top_k + 同 model
      → 第二次不再调 LLM
- [x] 多轮请求（history 非空）一律不查不写缓存
- [x] 语义命中：同库**同 mode + top_k + model** 下余弦 ≥ 阈值（默认 0.78，可配可关）
      才命中，answer/sources 按缓存原样返回 —— 参数必须参与匹配，否则对话页的
      「条数 / 模型切换」会被缓存静默吞掉（测试照出后修正）
- [x] 文档上传 / 删除成功后该 kb 缓存全部失效；删库走 FK 级联清缓存
- [x] 容量上限 LRU：超过 `CACHE_MAX_ENTRIES` 淘汰 `updated_at` 最旧的；不做 TTL
- [x] 流式命中：`sources` 照常先发，答案按段重放成 `token` 事件，`done` 带 `cache_hit`
- [x] 缓存读/写/失效任何异常都不影响问答主链路（warning 留痕）
- [x] 真环境评测：同义改写能命中（10.8s → 0.3s）、跨库串扰与易混意图对不误命中
      （`scripts/k6_cache_eval.py`，报告 `docs/eval/k6-cache.md`）
- [x] 双端测试全绿；`vue-tsc` / `vite build` 通过

## 依赖
- 前置积木：`K2-管线单例`（缓存随 lifespan 装配、共用 session_factory）、
  `K0-真实 Embedding`（语义命中的余弦只有在真向量上才有意义）

## 不做什么（边界）
- 多轮 / 带 conversation_id 的提问不缓存（改写结果依赖会话上下文，键爆炸且收益低）
- 不做 TTL（kb 级失效已保证不给旧答案）；不做 chunk 级精细失效（kb 级全量）
- 不复用 QaLog 建缓存（日志是"发生过的事实"，缓存是"可失效的应答"）
- 「缓存」徽标只在当次会话内显示，不落库（刷新后消失，反馈才需要持久化）

## 失败点 / 风险
- **语义缓存给错答案**是唯一实质风险 → 阈值 0.95 保守起步 + 评测护栏
  （同义对要命中 / 易混意图对与跨库串扰不许命中）+ `.env` 一键关
- 缓存写失败拖垮问答 → 所有缓存路径独立 try/except + warning
- 并发写同一键 → 唯一约束 + 短事务 upsert
