# 项目文档

本目录用**积木式开发**方式组织：每个功能都是一块积木，有独立的需求卡片和进度记录。
任何大目标（如某个"阶段"）都会先拆成小的功能积木，一次只做一块、做完即验证。

## 文档结构

| 文件 | 作用 |
|---|---|
| `requirements/` | 需求卡片：每个功能积木一张，写清楚做什么、验收标准、依赖 |
| `progress-log.md` | 进度日志：所有积木的状态总表（完成/进行中/待办/失败/回退）+ 迭代记录 |

## 工作流程

1. 拆积木：把大目标拆成小块功能，一次只做一块
2. 写卡片：动手前先写该积木的需求卡片（用 `requirements/TEMPLATE.md` 模板）
3. 实现 + 验证：做完立即用测试/demo 验证
4. 记进度：更新 `progress-log.md`，记录状态与验证结果
5. 汇报：向用户说明做了什么、完成了什么、失败了什么
