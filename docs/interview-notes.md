# 面试问答卡 —— EnterpriseRAGSystem

> **用途**：求职作品集配套。每题按「面试官的问法 → 回答要点 → 实测证据 → 追问预案」组织，
> 证据里的数字全部来自仓库实测，面试时可现场翻代码对质。
> 证据出处统一标文件路径；深挖细节见 `docs/bugfix-log.md`（50 条）与各需求卡。

---

## 元方法论（先背这四条，所有题都往这上面收）

1. **先量后改**：任何阈值 / 判据 / 开关，先写测量脚本拿数字，再定值，并用护栏测试钉住。
2. **设计先过实测**：架构直觉必须过一次真实写路径——bugfix #48/#49/#50 三连都是
   「设计推演通过、实测当场翻车」。
3. **降级要诚实**：「没做」和「做了但坏了」要区分；失败要点名原因与出路，不吞异常。
4. **归因分离**：一个数字变好，先问是哪个因素贡献的（如「异步化只解阻塞，
   砍时长的是批次调参」），不混在一个数字里邀功。

## 一、架构与工程决策

### Q1 「这个项目里最难的技术决策是什么？」→ 双阈值拒答（L1）

**要点**：`similarity_threshold=0.40` 只是召回粗筛，但 kb_2 实测库外噪声**会高于**
粗筛线照样进 prompt，拒答全靠 LLM 自觉——换更弱的模型就失守。解法是组合证据门：
**向量候选 raw 余弦最高的一条 < 0.48 且 关键词路证据不足（覆盖 <2 个查询词）→
直接返回标准拒答，零 LLM 调用**。只挂在 hybrid 模式（vector 模式没有关键词这条证据）。

**证据**：kb_2 库外 max 最高 0.4727 / 库内 max 最低 0.7536（干净间隙）；门触发实例
「美国站的退货窗口…」2665ms/sources=5 → **228ms/sources=0**。
出处：`docs/requirements/L1-dual-threshold-refusal.md`、`scripts/measure_refusal_gate.py`。

**追问预案**：
- 「阈值怎么定的？」→ 逐问测量脚本（退出码 1=误杀、2=门形同虚设），护栏测试钉住
  「默认值落在实测间隙内」；语料 / embedding 变更必须重测。
- 「为什么不直接调高 similarity_threshold？」→ kb_2 库内最弱 0.4652 < 库外最高
  0.4726，两条分布**重叠**，单阈值无论调多高都会误杀库内问题；所以分层：0.40 管召回、
  0.48+覆盖度管拒答。
- 「关键词路为什么不用 score？」→ chroma 给「命中词数」、pgvector 给 `ts_rank`，
  **量纲不通**，字面阈值换存储就静默失准；覆盖度（正文覆盖几个查询词）是无量纲口径。

### Q2 「审计日志为什么不给 kb_id 设外键？」（L2）

**要点**：审计是**历史事实**——删库恰恰是最需要留痕的动作，级联删除等于让记录自杀。
对比同库的 `QaLog`（随 KB 级联，因为「库没了日志无意义」），两者语义相反刻意不同。
配套设计：`actor_id`（可空）+ `actor_name`（恒填）双字段——撞库探测**不存在的用户名**
时 actor_id 为 NULL，但「谁在试」这条信息只有 actor_name 能承载。

**证据**：`test_kb_create_delete_audited_and_survives_deletion`——删库后按 kb_id 过滤
仍查到 create 与 delete 两条。出处：`app/core/models.py::AuditLog`。

### Q3 「审计和业务操作的事务关系怎么处理？」（L2 / bugfix #49）

**要点**：按路径二分。**成功路径**写请求会话、与业务同事务——操作成功 ⇔ 留审计，
回滚同亡（没做成的事不留成功假象）；**失败路径**（401 登录失败）走独立短会话立即提交
——因为路由 raise 会触发请求会话 rollback，挂上去的失败审计会跟着消失。

**证据**：最初设计「全程独立短会话」，实测 5 failed——成功路径请求会话已 flush 持有
SQLite 写锁，第二会话必撞 `database is locked`，且被 best-effort 吞掉 = **审计静默丢失**
（`assert total == 3` 抓到 `0 == 3`）。教训：架构直觉要过真实写路径；
凡吞异常的挂钩，测试必须直接断言落库结果，不能只断言业务响应。

### Q4 「为什么管线要做成单例？」（K2）

**要点**：实测每构造一个 OpenAI client 约 **650ms**（httpx 要建 3 个 SSLContext），
每请求重建管线 = 白送这段时间。FastAPI lifespan 装配一次挂 `app.state`，路由只取用；
摄取与问答共用同一份向量库与 embedding。配套细节：`get_rag` 在 lifespan 未触发时抛
**带指引的** RuntimeError（`TestClient` 忘用 `with` 是最常见现场）。

**证据**：`scripts/k2_assembly_bench.py`；AGENTS.md「运行时装配」节。

### Q5 「多供应商怎么设计的？」（K0）

**要点**：LLM / Embedding / Rerank **三插槽独立解析**供应商，留空走
`rerank → llm → rag` 兜底链——LLM 和 Embedding 指向不同厂商是常态而非特例。
一个反直觉的实测：百炼的 rerank **不在 OpenAI 兼容层**（`{base_url}/rerank` 404），
必须走原生端点且响应在 `output.results` 不是顶层 `results`——所以有独立的
`DashScopeRerank` 实现，`build_reranker` 对 bailian 特判。
**换 embedding 维度必须重建向量集合**（维度建集合时钉死），配套
`reindex_embeddings.py` 从 SQLite 的 Chunk 重新编码、不需要原始文档。

## 二、检索质量

### Q6 「命中阈值 0.40 是怎么定的？」

**要点**：不是拍的——先写 `measure_similarity_margin.py` 实测：kb_1 库内 rank-5 raw 余弦
最低 0.512、库外最高 0.375，0.40 落间隙内且不贴边（贴边=过拟合小语料）。
kb_2 上两条分布**重叠**（0.4652 vs 0.4726）→ 明确降级为「召回优先的粗筛」，
拒答交给 L1 门 + 模型。**换语料 / 加文档 / 换 embedding 必须重测**，脚本退出码判定。

### Q7 「语义缓存的阈值呢？」（K6）

**要点**：同样是量出来的：20 对探针实测**同义改写最低 0.8092、易混意图最高 0.7559**，
取间隙内 0.78。两个工程教训：①缓存键必须含 `mode+top_k+model`——否则对话页调参数
被缓存静默吞掉；②做 A/B 回归必须 `CACHE_ENABLED=false`——L1 验收时门关那轮 16 问
平均 23ms 全部缓存命中，**测了个寂寞**。

### Q8 「混合检索里发现过什么反直觉的事？」

**要点**：「元数据块」陷阱（bugfix #41-A）——文档控制页 / 修订记录在**向量路**语义太泛
无害，但在**关键词路**是天然高分选手，混合检索会把它顶到第 1，而它不含答案。
判定方法：`POST /inspect` 分别用 vector 与 hybrid 跑同一问，**两路名次差异大的块就是可疑块**。
治理：修订记录写「新增第四章」而不是复述正文关键词。

## 三、工程纪律（差异化最强的一组）

### Q9 「测试全绿但功能没生效，你怎么办？」（bugfix #48 —— 必讲题）

**要点**：L1 第一版判据含「关键词路 0 命中」：7 个专项单测全绿、473 项回归零红——
但真实分词器（中文重叠 2-gram）**永远造不出**「关键词路为空」的局面（任何问句都能
切出碰上的词），结果双库 6 条库外探针**全部漏网、门一次都没触发**。单测用 stub 造出了
现实中不存在的输入。修法：改成 `lexical_overlap` 覆盖度判据。
**教训**：测试证明机制成立 ≠ 证明它在真实数据上成立；只有端到端能触发一次的实测才算数。

### Q10 「你的测试怎么保证不出网、不烧线上额度？」（bugfix #46）

**要点**：`tests/conftest.py` 把供应商钉死 mock——但关键是**夹具必须 session 级**：
pytest 按作用域从大到小建夹具，函数级 setenv 会在模块级 `TestClient(app)` 进 lifespan
建完管线**之后**才执行 → 管线绑上 `.env` 的真实供应商，测试真实出网烧额度。
另一个批次纪律：PG-gated 用例要**按文件点名跑**（13 个带闸门的文件，实测 137 passed），
整目录混在 pgvector 环境会染红 14 个硬编码 SQLite 路径的离线用例。

### Q11 「怎么证明新写的回归测试真的能抓 bug？」（K9）

**要点**：给已修 bug 补的测试**写完就是绿的**，这不能证明任何事。纪律是**反向验证**：
把源码临时改回有 bug 的写法，确认测试变红，再改回来。落地实例：L3 的 OCR 测试
废掉弱页判定后 4 例变红；L2 审计的 best-effort 用例顺手抓到 `_build_log` 在 try 块外的
真缺陷（构造抛错把登录打成 500）。

### Q12 「讲一个『安装成功但不能用』的坑」（bugfix #50）

**要点**：`[ocr]` extra 装进 Docker 镜像、构建成功、冒烟 10 组断言全过——但扫描件
上传报「需要安装 OCR 组件」。根因：opencv 的 cv2 在 slim 镜像缺 `libxcb.so.1` 等原生库，
import 失败被 `available()` 的 ImportError 降级**吞成「未安装」**，错误信息还把方向
指到 pip install（实际缺系统库）。修：apt 层补 `libgl1 libglib2.0-0 libxcb1` +
`available()` 记录 ImportError 原文。
**教训**：wheel 落盘 ≠ import 成功，Python 依赖进容器要做 import 冒烟；降级错误信息要
区分「没装包」和「装了但坏了」；验证交付功能必须走真实触发路径——文本上传的通用冒烟
覆盖不到 OCR 冷路径。

## 四、可观测性与异步

### Q13 「线上出问题怎么定位？」

**要点**（K8）：`X-Request-ID` 贯穿每个响应与每一行日志（LogRecordFactory 注入，
不是 handler filter——换 handler 不丢字段）；用户报障给 request_id，运维一条 grep
拉出该请求全部日志行。两个深坑：①未处理异常处理器跑在**中间件之外**
（ServerErrorMiddleware 用自己的 send），500 响应头必须处理器自己设、日志上下文必须
用 `request.state.request_id` 重建；②「检索零命中 / 重排退化」在 INFO 下是**刻意静默**的
（每次检索都走到，INFO 会淹掉正常日志），排查这类问题先开 DEBUG。

### Q14 「异步摄取怎么设计的？」（K4）

**要点**：上传 202 立即受理 + `IngestionJob` 六阶段（parsing→…→done/failed）+
`done_units/total_units` 进度（**按批更新**而非每切片，SQLite 单写锁下高频写会抢锁）；
原件确定性路径 `data/uploads/{doc_id}.{ext}` 支持失败重试；启动自愈把停机时卡住的
job 置 failed（进程内线程池随进程消失，不标失败前端就永久转圈）。
**归因分离话术**：异步化只让 UI 不阻塞，**总时长是 embedding 批次 16→25 砍的**
（400 切片往返 25→16 次），两个数字不混在一个功劳里。

## 五、产品与前端

### Q15 「LLM 输出怎么保证前端能正常显示？」

**要点**：前端**没有** markdown 渲染器（全仓无 marked / v-html），模型写 `**加粗**`
界面就显示星号。解法在 system prompt **点名**禁 `**` / `*` / `#`——只写「不要复杂格式」
模型不照做，规则要列具体符号。配套契约：拒答文案字面「资料库中未找到相关信息」
被 `NO_HIT_ANSWER` 常量与评测判分同时依赖，改文案会把评测改坏（有测试钉住）。

### Q16 「用户说『知识库是空的 / 答案变差』，你怎么排查？」

**要点**：先分清**哪套环境**——本地开发（5173/8000，SQLite+Chroma，真实 embedding 1024 维）
与 Docker 交付（8080/18080，PG+pgvector，mock 64 维）数据不通、检索不同级。
在交付栈上看到空库或质量差**不是 bug**，是空库 + mock 级检索。先确认环境再查代码。
