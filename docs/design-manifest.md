# 前端落地方案（按本项目实际功能定制）

> **本文档的立场**：不套任何后台模板。
> 我们是**知识库问答产品**，不是 CRUD 后台 —— 10 个页面里只有 2 个是真表格页。
> 外部参照（Soybean Admin 等）只借 4 条通用原则和少数可量化数值，
> **形态一律按自己的功能来**。
>
> 与 [design-guide.md](design-guide.md) 的关系：那边给硬规则（禁紫蓝渐变、品牌色 5-10%、
> 圆角分层、双字体），这边给**每一页具体改什么**。冲突时以 design-guide.md 为准。
> 本文档是前端改版方案的唯一来源，不另设"外部参照文档"。

## 一、先盘点：我们实际有什么

| 页面 | 真实性质 | 主视觉 | 该不该套后台模式 | 优先级 |
|---|---|---|---|---|
| **Chat** | **产品核心** | 会话栏 + 消息流 + 输入区 | ❌ 后台模板里根本没有对话页 | **P0** |
| **KbsList** | **卡片网格**（不是表格） | 知识库卡 × N，卡上 5 个操作 | ❌ | **P0** |
| DocList | 面包屑 + 上传 + 表格 | 文档表 | ✅ 少数适用 | P1 |
| QaLogs | 表格（可展开答案） | 问答记录表 | ✅ 少数适用 | P1 |
| InspectBench | **调试台** | 参数区 + 命中切片列表 | ❌ 更像开发者工具 | P2 |
| Diagnostics | **数据看板** | stat 卡 + 失败分组 + 一致性 | 部分 | P2 |
| DocHealth | **数据看板** | stat 卡 + 死文档表 + 热力条 | 部分 | P2 |
| Login / Register | 表单页 | — | — | P3 |

**关键判断：Soybean 那套「筛选卡 + 表格卡」只适用于 DocList 和 QaLogs 两页。**
对 Chat、KbsList、InspectBench 完全不适用。**上一版方案把这条写成了通用建议，是错的。**

## 二、全局：统一 4 件事（一次改完，全站受益）

| 项 | 现状问题 | 统一为 |
|---|---|---|
| 间距刻度 | 24 / 20 / 16 / 12 / 8 混着用（`.layout-main` 24px、Chat 消息 20px、stat-grid 12px…） | **16px 一个单位**：页面 padding 16、卡片间距 16、卡内 padding 16、紧凑处 8 |
| 卡片规范 | 已统一（白底 + 1px 边框 + 8px） | 保持；**明确不用 box-shadow** |
| 字体层级 | h2 22px、h3 20px、sidebar-title 15px、kb-name 16px…没有层级 | `页面标题 20 / 卡片标题 15 / 正文 14 / 辅助 12` 四级，只准用这四级 |
| 状态色 | 语义色已用 Element 默认 | 保持；**彩色只许出现在状态表达上**（tag、分数条、统计卡），按钮不要五颜六色 |

```css
/* style.css 追加：布局刻度 */
:root {
  --app-gap: 16px;      /* 唯一间距单位 */
  --app-gap-sm: 8px;
  --fs-page: 20px;      /* 页面标题 */
  --fs-card: 15px;      /* 卡片/区块标题 */
  --fs-body: 14px;      /* 正文 */
  --fs-hint: 12px;      /* 辅助/提示 */
}
```

## 三、逐页方案

### P0-a｜Chat.vue —— 最该改的一页（582 行，占项目前端 20%）

这是产品的门面，也是面试官唯一会认真看的页面。已定位到 **5 个具体问题**：

**1. AI 气泡和页面背景同色（真 bug）**

`.chat-msg--assistant .chat-msg-content { background: #f5f7fa }`（Chat.vue:484-487）
而 `body { background: var(--app-bg) }` 且 `--app-bg: #f5f7fa`（style.css:19）。
**两个颜色完全一致，AI 消息的边界在灰底上根本看不出来。**

```css
.chat-msg--assistant .chat-msg-content {
  background: #fff;                          /* 改白底 */
  border: 1px solid var(--el-border-color-lighter);
}
```

**2. 气泡用 `float` 布局（老写法，脆弱）**

Chat.vue:495-507 用 `float: right/left` + `.chat-msg::after { clear: both }`。
消息结构一复杂（比如加了引用芯片）就容易塌。改 flex：

```css
.chat-msg { display: flex; flex-direction: column; margin-bottom: var(--app-gap); }
.chat-msg--user { align-items: flex-end; }
.chat-msg--assistant { align-items: flex-start; }
.chat-msg-content { max-width: 78%; padding: 12px 16px; }   /* 85% → 78%，阅读宽度更舒服 */
```
（顺带把 `float` 和 `::after` 那段删掉）

**3. 溯源 —— 本产品最大卖点，被藏起来了**

现在引用是 `el-collapse` 折叠面板（Chat.vue:70-82），用户必须主动点开才看得到。
而"可溯源"恰恰是这个项目区别于普通聊天机器人的地方。

改成**引用芯片**：答案下方一排小卡片，默认只显示文件名 + 相似度，点击才展开原文。

```
[全球优选_供应商管理制度.pdf · 62%] [原料验收标准.pdf · 55%] …
                                        ↑ 点击展开对应切片原文
```

配合 K1（真流式），`sources` 事件会在答案之前到达 → **答案还在打字时，引用芯片已经显示出来了**，
观感上"有据可依"的说服力直接拉满。这是 K1 + 本条改造的叠加红利。

**4. 没有检索状态反馈**

现在发送后到第一个字之间是完全空白的（K1 修好真流式之前尤其明显）。
K1 落地后接 `stage` 事件：

```
正在改写问题… → 正在检索资料… → 正在重排… → 正在组织答案…
```

**5. 输入区按钮高度硬编码**

`.chat-input-area .el-button { height: 60px }`（Chat.vue:579-581）—— 靠运气和
`textarea rows=2` 对齐。改成 `align-self: stretch`，让它自适应。

---

### P0-b｜KbsList.vue —— 卡片网格是对的，但按钮太花

现状：每张卡 5 个文字按钮，颜色依次 **primary / success / warning / 默认 / success**
（KbsList.vue:30-34）。一眼看过去五颜六色，**违反"彩色只表达状态"**，
也是最容易被说"像后台管理系统"的地方。

改成：**一个主操作 + 其余弱化**

```
[ 进入对话 ]        ← 实心主色，唯一强调
文档  质检  体检  健康   ← 灰色文字按钮，hover 才变色
```

理由：进知识库后 90% 的人要的是"对话"，其余四个是低频的运维入口。
主次拉开，卡片立刻干净。

---

### P1｜DocList / QaLogs —— 只有这两页适用"表格改造"

（Soybean 那套筛选+表格的模式，到这里才有用武之地）

- 表头降一级：`13px`、灰字 `#909399`、浅灰底 `#fafafa`，让用户第一眼看数据
- 行高：cell 上下 padding 12px（约 44px 行高）
- **状态列用 tag**：`已索引=绿 / 处理中=橙 / 失败=红`（DocList 的状态列天然适配）
- 行内操作只留 2 个文字按钮，多的收进「更多」下拉

- DocList 特有：上传区目前是工具栏按钮，K4 做完会有进度条 → 预留"处理中"行样式
- QaLogs 特有：展开区用 `<pre>` 展示答案全文，建议加等宽字体和最大高度

---

### P2｜InspectBench —— 调试台，别按卡片排版

这是**开发者工具**，不是信息展示页。现有控件（检索模式 / 重排 / top_k / 检索按钮）
挤在一行（InspectBench.vue:23-41），参数一多就换行错位。

改：参数收进一张「检索参数」卡（横向 flex，允许换行），下方是命中切片列表。
命中项展示**检索分 / 重排分**双分数条 —— 这是 I1 的核心价值，值得给足视觉空间。

---

### P2｜Diagnostics / DocHealth —— 两个看板页要"长得一样"

两页都自己写了 `.stat-grid` + `.stat-card`，**样式重复且可能漂移**。
（Diagnostics.vue:231-244 与 DocHealth 各一份）

改：抽一个 `StatCard.vue` 组件（数字 + 标签 + 可选状态色），两页共用。
同一份数据看板语言，比多写一遍样式重要。

---

### P3｜Login / Register

保持现在的简洁。**明确不抄 Soybean 的紫蓝渐变登录背景** ——
那正是 design-guide.md 第一条禁的。

## 四、从外部参照里借的，只有这 4 条

以 Soybean Admin（MIT，Vue3 后台模板）为样本，实测提炼：

| 借什么 | 数值 / 做法 |
|---|---|
| 密度刻度 | 侧边栏 220px、顶栏 56px、基础字号 14px/21px、卡片 padding 16px |
| 靠底色分层 | 内容区灰 `#f5f7fa` + 白卡片，**不用阴影**（我们已做对） |
| 彩色只表达状态 | 95% 黑白灰，红绿黄蓝只在 tag / 分数条 / 统计卡 |
| 圆角克制 | 卡片 8px、按钮 4px（我们已有变量，保持） |

**不借的**：主色（它是靛蓝 `#6366F1`，正是我们禁的"AI 默认紫蓝"）、
多标签页栏（成本高、对 10 个页面收益低）、"筛选卡+表格卡"的通用形态（只适用 2 页）、
Naive UI 组件库（换库不值）。

## 六、不做什么

- 不换组件库（Element Plus 够用，问题在没调教）
- 不引入 Tailwind / UnoCSS（现值已够，加工具链是纯负担）
- 不做多标签页栏、不做右侧设置抽屉（规模不值得）
- 不做深色模式（先把浅色做对）
