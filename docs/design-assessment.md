# 前端去AI味 — 项目适配评估

> 基于 `docs/design-guide.md`（原始方案：宋宇），针对 EnterpriseRAG 的实际评估。
> 日期：2026-08-07

---

## 总体评价

方案含具体 CSS 值和理由，不是空谈审美的 AI 生成品。核心洞察准确：AI 前端有固定的紫蓝渐变、等分三列、Inter 字体、统一圆角的"指纹"。**方案值得采纳，但需要针对企业 CRUD 工具做裁剪。**

---

## 分维度: 哪些适用、哪些需要调整

### ✅ 直接采纳（改动小、收益大）

| 规则 | 项目现状 | 改造方式 |
|---|---|---|
| **品牌色（非紫）** | `#409eff` Element Plus 默认蓝，全站铺满蓝色按钮/链接 | 选墨绿 `#0f6e56` 或深蓝 `#1a56db`，覆盖 Element Plus CSS 变量 `--el-color-primary` |
| **圆角分层** | Element Plus 默认，卡片 8px，按钮 4px 已有区别但不一致 | 统一为 L1 容器 12px、L2 卡片 8px、L3 按钮 4px |
| **阴影禁厚重** | 当前已较克制 `0 1px 4px` ✓ | 保持即可，卡片用 `border` 替代阴影区分层级 |
| **动效单属性** | 卡片 `box-shadow 0.2s` ✓ | 保持 |
| **文案无禁止词** | 当前中文直述，无 AI 味 ✓ | 保持 |

### ⚠️ 需裁剪（企业工具有特殊约束）

| 规则 | 冲突点 | 建议折中 |
|---|---|---|
| **双字体（衬线+无衬线）** | 表格、代码块、chat 消息用衬线标题很怪 | 保留双字体思路但改为：**页面标题/logo 用衬线**，正文/表格/chat 全用无衬线。中文用 Noto Serif SC + Noto Sans SC |
| **不等分网格** | 知识库列表是等权卡片，`auto-fill` 是合理的响应式方案 | 只在有明确主次关系的页面用不等分（如将来管理后台的统计面板 7fr:5fr） |
| **出格元素（负 margin 重叠）** | 表格和表单需要精确对齐，出格会破坏可读性 | 放弃。用颜色/字体对比代替空间"出格"来制造视觉层次 |
| **标题左对齐** | 登录/注册页居中卡片是几十年的 UX 惯例 | 保持居中。但知识库详情页标题可改左对齐 |

### ❌ 不适用

| 规则 | 原因 |
|---|---|
| `#000000` 深色模式 | 当前无深色模式需求，V2 再考虑 |
| 骨架屏 > spinner | 当前是简单 spinner，对 CRUD 列表加载足够了。骨架屏优势在多区块异步加载的营销页 |

## 推荐的改造优先级

| 优先级 | 改造内容 | 涉及文件 | 预估工作量 |
|---|---|---|---|
| P0 | 品牌色切换（覆盖 Element Plus 变量） | `style.css` | 30 分钟 |
| P1 | 字体栈（思源宋体标题 + 无衬线正文） | `style.css` | 20 分钟 |
| P2 | 圆角分层统一 | `style.css` + 各组件 | 1 小时 |
| P3 | 阴影→边框过渡 | 各组件 CSS | 30 分钟 |
| P4 | 个别页面布局微调（不等分网格） | 统计页面（尚无） | — |

## 与当前项目的关系

当前 V1 30 块积木已全部完成。前端改造属于"视觉 polish"而非"功能积木"。

**建议路线**：
1. 先把设计指令文件纳入项目（`docs/design-guide.md`）✅ 已完成
2. 按 roadmap 下一步做功能（管理后台或其他进阶功能），同时把色彩/字体/圆角作为新页面的默认样式
3. V2 启动时统一做一次视觉翻新，而非现在回头改已完成的 V1 页面

**理由**：功能完整 > 视觉打磨。且现在改了 V1 页面后，后续新页面如果用不同设计语言，反而造成视觉割裂。
